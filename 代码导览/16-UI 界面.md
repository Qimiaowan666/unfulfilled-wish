## UI 界面

**定位**:游戏所有屏幕显示层的总和——HUD(玩家/敌人/boss 血条)、菜单(主菜单/暂停/死亡/胜利)、弹窗(交互提示/处决提示/奖励/确认)、剧情对话、商店、角色面板(状态/装备/背包/技能),以及 boss 登场/击破两段过场演出。它本身几乎不持有游戏逻辑,而是**订阅各业务系统的事件 + 反过来调它们的方法**,把数据可视化并把玩家点击回传。

**关键脚本**(`Assets/Scripts/UI/` 下,路径相对该目录):

*血条 / HUD*
- `PlayerHealthBarUI.cs:8` — 玩家 HUD(血/虚血/体力/韧性)。常驻 Bootstrap,每次 `sceneLoaded` 重新 `FindAnyObjectByType<PlayerStats>` 绑定;受击时 HUD 抖动+血条闪白(`PlayerHealthBarUI.cs:125`)。
- `BossHealthBarUI.cs:9` — 通用 boss 血条(场景级),`Start`/`SaveSystem.AfterApply` 时 Find 标记 `isBoss` 的敌人绑定;名字/配色读 `boss.profile`;登场模式下先藏,`Update` 自愈式露出(`BossHealthBarUI.cs:41`)。
- `EnemyHealthBarUI.cs:4` — 小怪头顶血条(挂在敌人 prefab 上)。`LateUpdate` 脚本驱动统一定位/缩放(`:63`),受击时 `Show` 2.5s 后自动隐。
- `LiquidBar.cs:8` — 液体波浪条,弹簧追随目标值,液面速度驱动波幅;`SetFill(t, instant)` 由血条调用。
- `PersistentHUD.cs:6` — 只做"HUD Canvas 跨场景常驻+唯一"的薄壳(仿 PersistentEventSystem)。

*菜单 / 系统弹窗*(均常驻单例,挂 Bootstrap)
- `PauseMenu.cs:14` — 统一暂停菜单 + 存/读/删档子面板 + 设置子页 + 内置确认弹窗。订阅 `GameManager.OnGamePaused/Resumed`;`Update` 里按 ESC 调 `GameManager.TogglePause`;主菜单复用其 `OpenLoadStandalone/OpenSettingsStandalone`。
- `GameOverUI.cs:7` — 死亡界面,**纯代码程序化构建** UI(唯一一个,其余都靠 prefab),监听 `GameManager.OnGameOver`。
- `VictoryUI.cs:8` — 通关胜利画面,`Show()` 由 `BossBattleManager`/`VictoryGate` 调。
- `MainMenuUI.cs:9` — 主菜单(新游戏/继续/读档/设置/退出),逻辑薄,委托 SaveSystem + PauseMenu 子面板。
- `ConfirmDialog.cs:10` — 独立确认弹窗(场景级,主菜单用),静态 `Show(onYes, onNo)`,与暂停菜单内置的那套确认无关。
- `RewardPopupUI.cs:8`、`InteractPromptUI.cs:6`、`ExecutePromptUI.cs:6` — 奖励弹窗 / 交互提示木框 / 处决提示木框。后两者跟随世界点 `WorldToScreenPoint` 显示。

*对话 / 商店*
- `DialogueUI.cs:11` — 剧情对话框,`Play(sequence, onDone)` 逐句、空格/回车/左键推进、暂停时间;`IsPlaying` 静态供别处闸门判断。
- `ShopUI.cs:8` + `ShopRowView.cs:8` — 商店界面 + 单行模板。`Open(ShopSystem)` 拉数据建列表,点行弹详情,确认走 `shop.BuyItem/BuyEquipment/BuySkill`。

*角色面板*(`CharacterPanel/` 子目录)
- `CharacterPanelUI.cs:11` — 面板控制器(C 开关,1-4 切页),订阅四大系统的 change 事件刷新,暂停时间 + 隐藏 HUD。
- `CharacterPanel/Views/CharacterPageView.cs:5` — 四页 View 抽象基类(`Refresh/Show/Hide`)。
- `EquipmentPageView.cs:6`、`InventoryPageView.cs:8`、`SkillsPageView.cs:4` — 装备/背包/技能三页具体实现(状态页在 prefab 里,无独立 View 脚本)。
- 行/格/详情绑定壳:`DetailPanelView.cs:8`(右栏详情)、`StatRowView.cs:7`、`ListItemView.cs:9`、`ItemSlotView.cs:9`(后两者用 `IPointerClickHandler` 区分左右键)。

*过场演出*
- `BossNameCard.cs:9` — boss 登场揭幕名牌(黑条展开→罗马名淡入→中文名逐字弹入),内容由 `BossProfile` 驱动,文字用烘焙 PNG 而非 TMP(绕开中文字体被乘黑的坑,`:8`)。
- `BossFinishUI.cs:10` — 击破演出(顿帧/慢放/压暗/白色剪影/水墨泼溅/碎屑/击破名牌),常驻 Bootstrap,`Play(boss, onComplete)`。

**怎么工作**

整套 UI 有三种典型范式,值得分别记:

1. **常驻单例 + 静态访问/静态状态闸门**。绝大多数全局 UI(PauseMenu/DialogueUI/ShopUI/VictoryUI/CharacterPanelUI/BossFinishUI/RewardPopupUI/Interact/Execute Prompt)都是 `Instance` 单例,`Awake` 里 `transform.SetParent(null)+DontDestroyOnLoad`,实例摆在 Bootstrap 场景。它们大量暴露 `static bool IsOpen/IsPlaying`,互相**当闸门**用:`PauseMenu.CanOpenPause()`(`PauseMenu.cs:170`)一口气检查 `ShopUI.IsOpen || CharacterPanelUI.IsOpen || VictoryUI.IsOpen || DialogueUI.IsPlaying || BossIntroTrigger.Sequencing || BossFinishUI.IsPlaying || MinotaurBoss.PhaseTransition`,任一为真就不让开暂停;CharacterPanelUI 同理(`CharacterPanelUI.cs:80`)。

2. **HUD = 事件订阅 + 重绑定**。血条不轮询,而是订阅业务事件:`PlayerStats.OnHPChanged/OnGhostHPChanged/OnStaminaChanged/OnDamaged`、`PoiseMeter.OnPoiseChanged`(`PlayerHealthBarUI.cs:109`)、`EnemyBase.OnHPChanged/OnDied`(`EnemyHealthBarUI.cs:35`)。因为玩家/boss 单例不跨场景常驻而 HUD 常驻,所以玩家 HUD 在 `sceneLoaded` 重新 `Acquire()`(`PlayerHealthBarUI.cs:64`),boss 血条在 `Start` 和 `SaveSystem.AfterApply` 重新 Find+绑定。`LiquidBar` 把"目标值→弹簧追随→液面速度→波幅"分离,所以突然受击会荡、缓慢回体力只有涟漪。

3. **数据驱动的 View(布局在 prefab,脚本只填数据)**。除 GameOverUI 外,所有面板布局都在 prefab/场景里摆好,脚本仅持引用 + 跑逻辑。角色面板是最完整的例子:`CharacterPanelUI` 持 `CharacterPageView[] pages`,切页时调 `page.Show()/Hide()`(`CharacterPanelUI.cs:117`);各页 `Refresh()` 里 `ClearChildren` 容器后 `Instantiate` 行/格 prefab,用 `ListItemView/ItemSlotView/StatRowView/DetailPanelView` 这些薄绑定壳填数据并挂回调。装备页的装/卸全走右键、饰品右键进入"选槽预览"模式(`EquipmentPageView.cs:45`、`:77`),换装时 ▲▼ 预览属性差值(`:124`)。

数据流统一是:**业务系统事件 → UI 的 Refresh/Handle → 读系统当前值重绘**;**玩家点 UI → 回调调业务系统方法 → 系统发事件 → UI 再刷新**(角色面板/商店买东西后都是这条闭环)。

过场演出是协程编排:`BossFinishUI.Sequence`(`BossFinishUI.cs:79`)一条协程串起顿帧→白闪→压暗→把 boss 的 SpriteRenderer 临时换成剪影材质(`SwapToSilhouette`,`:208`,结束 `RestoreSwapped` 还原)→泼溅/碎屑→名牌→淡出→`onComplete`。期间把 timeScale 压到 0.0001 但用 `WaitForSecondsRealtime`/`UnscaledTime` 推进,并强制 boss Animator 走 UnscaledTime(`:99`)避免剪影定格。

**入口 & 触发**

- 常驻单例 UI 由 **Bootstrap 场景**里预先摆好的实例自我注册(`Awake`),不靠代码 new。
- **玩家行为触达**:按 ESC → `PauseMenu` 调 `GameManager.TogglePause`;按 C / 数字 1-4 → `CharacterPanelUI`;走近交互物 → `InteractTrigger`/`LockedDoor`/`VictoryGate`/`ChestInteract` 调 `InteractPromptUI.Show/Hide`;靠近被破韧敌人 → `ExecutePromptUI.LateUpdate` 自动找目标显示;开宝箱 → `ChestInteract` 调 `RewardPopupUI.Show`(`ChestInteract.cs:62/74`)。
- **系统事件触达**:玩家死亡 → `GameManager.OnGameOver` → `GameOverUI.Show`;暂停 → `GameManager.OnGamePaused/Resumed` → `PauseMenu.Open/Close`。
- **剧情/战斗编排触达**:`BossIntroTrigger` 调 `DialogueUI.Instance.Play`(`BossIntroTrigger.cs:130`)和 `nameCard.Play`(`:137`);`BossBattleManager` boss 击败后调 `BossFinishUI.Instance.Play(currentBoss, ShowEnding)`(`BossBattleManager.cs:102`),收尾再开 `VictoryUI.Show`;`VictoryGate` 玩家交互后也调 `VictoryUI.Instance?.Show()`(`VictoryGate.cs:67`)。
- 商店由 `ShopNPCTrigger` 调 `ShopUI.Instance.Open(shop)`(注释 `ShopUI.cs:7`)。

**依赖 & 被依赖**

它**用到**:`GameManager`(暂停/死亡/换场景事件与方法)、`PlayerStats`/`PoiseMeter`(玩家 HUD、角色面板状态)、`EnemyBase`/`BossProfile`(敌人&boss 血条、击破名牌、登场名牌)、`SaveSystem`(PauseMenu 存读删档槽、缩略图、`AfterApply` 重绑)、`GameSettings`(设置子页 BGM/SFX/全屏/分辨率)、`AudioManager`(几乎所有点击/开关/购买/击破都播一声)、`SceneNames`(游玩/非游玩场景判定与中文名)、四大库存系统 `EquipmentSystem`/`InventorySystem`/`SkillSystem`/`Player_SkillManager`(角色面板订阅其 change 事件并调 Equip/Use/Buy)、`ShopSystem`(商店购买)、`DialogueSequence`/`DialogueLine`(对话数据)。

它**被依赖**(谁反过来调它):`GameManager`(发事件被 PauseMenu/GameOverUI 接)、`BossBattleManager`(`BossFinishUI`+`VictoryUI`)、`BossIntroTrigger`(`DialogueUI`+`BossNameCard`)、`VictoryGate`(`VictoryUI`+`InteractPromptUI`)、`InteractTrigger`/`LockedDoor`/`ChestInteract`(`InteractPromptUI`/`RewardPopupUI`)、`MainMenuUI`(复用 `PauseMenu` 子面板 + `ConfirmDialog`)。此外 `PauseMenu.CanOpenPause` 和 `CharacterPanelUI` 把多个 UI 的 `IsOpen/IsPlaying` 当作互斥闸门读取。

**关键设计 / 易错点**

- **timeScale=0 的捕获/还原陷阱**:多个面板暂停游戏时 `previousTimeScale = Time.timeScale`,关闭再还原。如果在已经 timeScale=0 的时刻(对话/演出/已暂停)打开另一个面板,会把 0 存进去,关闭时把 0 还原 → 永久锁死。代码靠两道防线:① 开面板前用 `IsOpen/IsPlaying/Sequencing` 闸门挡住(`CharacterPanelUI.cs:80`、`PauseMenu.cs:173`);② 还原时把值钳到 >0(`ShopUI.cs:261`、`CharacterPanelUI.cs:208`)。改动 UI 的暂停逻辑时务必保留这两道。
- **常驻 HUD vs 场景级实体的重绑定**:HUD 常驻、玩家/boss 不常驻,所以**所有事件订阅必须在 `Unbind` 里成对取消**,否则旧实体被销毁后事件残留/重复。新增 HUD 元素记得照抄 Bind/Unbind 配对(`PlayerHealthBarUI.cs:84`、`BossHealthBarUI.cs:89`)。
- **boss 血条/演出用 alpha 而非 SetActive 隐藏**:`BossHealthBarUI.Hide` 走 `CanvasGroup.alpha=0`(`:168`),保证 `Update` 自愈和读档恢复仍能运行;`BossFinishUI` 也在 `OnSceneChanged` 里强制收尾(还原 timeScale/材质/IsPlaying,`:62`),避免演出中途切场景卡死。
- **中文文字烘焙成 PNG**:`BossNameCard` 和 `BossFinishUI` 的击破名牌都用烘焙 Image 而非 TMP 文本,注释明确是绕开"SimHei 字体材质把中文乘成黑色"的坑(`BossNameCard.cs:8`、`BossFinishUI.cs:264`)。新增中文大字演出别想当然用 TMP。
- **唯一的程序化 UI 是 GameOverUI**:它 `EnsureUI()` 全代码建 Canvas/Image/Button(`GameOverUI.cs:70`),sortingOrder=1100 盖一切;其余面板都"prefab 摆布局、脚本只引用",改外观找 prefab 不是改脚本。
- **左右键分流约定**:`ListItemView`/`ItemSlotView` 左键走 `Button.onClick`、右键走 `IPointerClickHandler`(`ListItemView.cs:38`)。装备页"右键=装/卸、左键=仅看详情"这套交互依赖此约定,改绑定时别混。
- **PauseMenu 里还内置了一套确认弹窗**(`ShowConfirm/AcceptConfirm`,`PauseMenu.cs:430`),与独立的 `ConfirmDialog.cs` 是两套东西,别搞混(后者主菜单用)。
- 历史包袱:`PlayerInputBuffer`、`HUDController`、`InventoryUI`/`InventorySlotUI`、`KeyPickup`/`LevelKeyManager` 已删除(见 git status 的 D),角色面板取代了旧 InventoryUI——文档/检索时别再引用这些旧类。
